## 上一章留下的问题

s14 的核心机制是一行代码：

```python
off = bus.on(event, fn)      # 注册返回撤销函数
...
for off in reversed(self._disposers): off()    # 卸载时逆序执行
```

它管用，但有一串问题它自己回答不了：

- 为什么**注册返回撤销函数**是对的？而不是"作者写一个 teardown 函数"？
- 为什么逆序执行就够了？谁保证的？
- 从运行中的系统里**单独撤下**一个组件（乱序撤回）时，为什么有时会出错？
- "恢复"到底是什么意思？`free` 之后堆布局不可能复原，那"回到初始"是什么？

这些问题的一般答案就是 deepseek-harness 底层框架 Cordis 论文 §3.1 的
**可逆效应（revertible effects）**。

---

## 这一章解决什么

把 s14 的一行代码讲成一个小理论：

```
效应 = 修改 + 它的逆        Γ → Γ × (Γ → Γ)
运行时追踪：逆压入累加器（accumulator）
恢复：把累加器按 LIFO 跑一遍
乱序撤回：需要独立性（交换性）
"回到初始"：读作观察等价
```

## 新增的核心概念

### 1. 每个原子效应自带单侧逆

三个设计决策，全在 `ctx.effect(forward, inverse)` 这一个签名里：

- **逆由调用者在施加处提供**。一个逆往往只在它作用的那一个状态下成立 ——
  `close()` 只能关"这个 fd"，必须由 `open()` 返回，不能预先登记。
- **逆只需要单侧成立**：`inverse` 能把施加后的状态带回施加前的状态即可。
  这是工程现实：`free` 不回堆布局，但"资源被回收了"已经够了。
- **复合的逆自动按反序复合**（扭曲复合）。作者只需为每个原子效应手写逆，
  任意复合的逆零成本推导。

### 2. 健全不变量

```
accumulator(state) == 初始状态
```

每次 `effect()` 都保持它不变。所以**完整恢复是一个结构保证**，
不是"作者记得写 cleanup"的自觉。这正是 s14 的 `_disposers` 做的事。

### 3. 独立性（independence）

单组件场景 LIFO 免费成立。但真实系统里：

- 多个组件的效应**交错**发生
- 撤回一个组件时，它的逆会遇到**被别的组件移动过的状态**

此时逆是否仍成立是一个交换性问题：一个效应的所有变换
（正向 + 它产生的所有逆）与另一个效应的所有变换两两交换。
demo 第 3 部分给你看失败的样子：C1 的逆**完全正确**，但作用在
C2 移动过的状态上，撤回后不是 0 而是 9。

### 4. 恢复的相等是观察等价

物理状态不可能逐位复原。所以"回到初始"读作：

```
两个状态相关 ⟺ 没有观察者能区分它们
```

而观察者被赋予的能力正是 s20 的 coeffect ——
**依赖定义了「恢复到什么粒度就算数」。**

## 最小架构图

```
  effect(f, g)                     recover()
  ┌──────────────┐               ┌──────────────┐
  │ state ← f(state)│            │ while acc:   │
  │ acc ← [g] + acc │            │   acc.pop()()│
  └──────────────┘               └──────────────┘
        │ 每次施加都保持：acc(state) == 初始状态
        ▼
   ┌──────────────────────────────────┐
   │ 单组件：LIFO 免费成立              │
   │ 多组件交错：需要独立性才能乱序撤回  │
   └──────────────────────────────────┘
```

## 为什么这样设计

### 为什么是"注册返回逆"而不是"作者写 teardown"

VSCode 的 `activate/deactivate` 把效应的创建和清理**分离在两个函数里**：
加一行注册，忘了加对应的清理 —— 静默、难查、必然发生。
而注册返回撤销函数在结构上杜绝了这种遗忘。

### 为什么逆序执行就够了

复合的逆按反序复合是**自动成立**的，不需要作者写任何顺序代码。
这是整章最"免费"也最重要的结构性质。

### 为什么乱序撤回需要额外条件

论文的推论 21：独立时 n 个逆**按任意排列**应用都回到初始态。
不独立时只能回到 LIFO（accumulator）——或者用 s20 的声明
（coeffect）强制"谁先停"的纪律。

## 真实系统里还有什么

- **witness（见证）**：论文的 𝔈* 要求每个逆**在所施加的状态上**真的可逆。
  我们没做运行时检查，靠作者的逆正确。
- **迭代器效应**：真实系统把 setup 拆成多步迭代，每步后可中止回滚（s21 会提）。
- **独立性是静态可查的**：Cordis 里"不同 key 的操作自动独立"（定理 40）——
  写不同 key 的组件天然可以乱序撤回。s20 的单源纪律保证了这个前提。

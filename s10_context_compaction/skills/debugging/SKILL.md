# 系统化排查

## 顺序（不要跳步）

1. **复现**：先跑一次，亲眼看到失败。看不到失败就不要开始改。
2. **读完整报错**：读到最后一行。真正的原因常在 traceback 底部，
   而不是最上面那个最显眼的异常。
3. **缩小范围**：只跑失败的那一个测试
   （`pytest tests/test_x.py::test_y -x`），不要每次跑全量。
4. **确认假设**：把你以为的值打出来。90% 的 bug 是
   "我以为它是 A，其实它是 B"。
5. **改一处，再跑**：一次只改一个地方。同时改三处，
   通过了你也不知道是哪处起的作用。

## 常见陷阱

- 报错行号指向的是**症状**，不是**原因**
- 测试之间共享状态：单独跑过、一起跑挂，多半是这个
- 改了代码没生效：检查是不是有缓存（`__pycache__`、装了旧版本包）
- "偶尔失败"通常意味着依赖了顺序、时间或并发

## 什么时候停下来

- 同一个假设试了 3 次都不对 → 假设本身是错的，回到第 4 步
- 改动开始越来越大 → 你在猜，不是在查
